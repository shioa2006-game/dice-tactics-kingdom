# DICE TACTICS: KINGDOM

タイトルから対戦・終局・再戦まで遊べる、スマートフォン縦画面向けのゲームです。元ゲームのコア・4難易度CPU・音声を引き継ぎ、Studioのキャラクターと石造りの盤面へ接続しています。外部パッケージのインストールは不要です。

## 起動

Node.js 18以上が必要です。Windowsではルートの **`launch.bat` をダブルクリック**。または、このフォルダで `npm start` を実行します。

通常版: **http://127.0.0.1:8150/**。使用中なら8151以降へ自動変更するため、起動ログのURLを確認してください。終了はサーバーのウィンドウで Ctrl+C。HTMLを直接開く `file://` では動作しません。

スマートフォンはPCと同じLANに接続して、起動ログの「同一 LAN」のURLを開きます。Windowsファイアウォール等の設定に左右されます。LANからの実機接続は未確認です。

通常起動では固定AP・人工局面・CPUデモは出ません。参照元と旧モックのフォルダは整理済みで、KINGDOM単体で起動できます。

## 操作

- タイトルで難易度と先手を選び、対局を開始。下部の「ダイスを振る」でAPを決定します。
- 携帯・PC共通で、駒を選択→「移動」→青緑の床を選択→「ここへ移動」で確定します。移動モードでは身体やHPより床を優先し、他の駒を薄く表示します。移動先は金枠・半透明のキャラクター・経路・消費APでプレビュー。「移動を取消」で駒の選択へ戻ります。ドラッグは常に見渡し操作です。赤枠の敵は通常の駒選択状態でタップして攻撃をプレビューします。
- 金の点線は直線射程の目安で、岩や駒の遮蔽を適用する前の表示です。敵を選ぶと次の手番に移動して攻撃する可能性と必要APも表示します。
- 足元は青緑の円＝味方、赤茶の菱形＝敵。HPは2〜4個の丸で、失ったHPは中抜きになります。HPはキャラクターより後ろの床層に描き、手前のキャラクターの頭や胴に重ねません。
- 選択すると下部に小さな肖像、名前・同職種番号、HP、行動状態、射程を表示します。密集している位置では候補から選べます。
- 盤面上の「部隊」「自軍へ／選択駒へ」ボタンは設けていません。ドラッグで見渡し、ミニマップで位置を確認します。自軍の選択だけではカメラは移動せず、CPUの画面外の行動には追従します。
- 攻撃前の移動は「戻す」。APや行動が残る場合の「ターン終了」は二度押しで確認します。
- 履歴・敵の射程・ルール・消音・設定は最下部。速度、移動プレビューの再タップ確定、控えめ演出、BGM/効果音/音量を保存します。BGMは初回の曲準備に数秒かかります。
- キー: **Space** ダイス、**1〜6** 自軍選択、**M** 移動モード、**Enter** プレビュー確定、**Esc** 取消/閉じる、**Z** 戻す、**E** ターン終了。移動モード・プレビュー中はEによる終了を抑止します。簡易設定ONでも移動先の初回タップは必ずプレビューです。

## 表示と参照元

マス97.5×54.6 CSS px。床・ダンジョン・キャラクターを従来の1.3倍に拡大（駒の床に対する倍率1.25は維持）。画面幅に合わせた盤全体の自動縮小は行いません。PCでは幅480pxまで、実機では画面幅を使います。射程4の対向する端マス全体は約487.5pxのため、スマートフォンではパンで周囲を確認します。端の対象・HPまで同時に収まるとは扱っていません。

採用ID: `king`、`warrior`×2、`archer`×2、`mage` ／ `demon-king`、`goblin`×2、`skeleton-archer`×2、`dark-mage`。キャラ定義・装備・方向別アニメーションは原本のままです。

初期配置と各駒の行動終了時に、その駒が敵の王の方向を向きます。待機中は敵王が移動しても向きを保ちます。移動・攻撃中は行動方向を向き、「戻す」では移動前の向きも復元します。王撃破後は最後の攻撃方向を維持します。上部の青緑・赤茶のバナーで両軍の残存数、ダイス強化段階、最大APを確認でき、下部は大きめのダイス・APと金色の主操作ボタンに整理しています。

奥2面の壁と松明、低い縁石、元の4障害物を低い石積みで描きます。パンはキャッシュ済みの描画面全体を動かし、石床・石積み・全アニメーションの生成を繰り返しません。

キャラクターの全1,648コマはStudioの描画から事前生成した可逆圧縮WebPで読み込みます。通常起動に画像生成やPythonは不要です。標準・高解像度の2組から1組だけ読み込み、画像取得に失敗した駒だけ従来の生成処理へ戻ります。生成方法・照合方法は [アニメーション画像](docs/ANIMATION_ASSETS.md) を参照してください。

## Git管理

リポジトリ: [shioa2006-game/dice-tactics-kingdom](https://github.com/shioa2006-game/dice-tactics-kingdom)。通常の作業ブランチは `main`、接続先名は `origin` です。

変更を確認して保存する基本手順:

```powershell
git status
git diff
npm test
git add <保存するファイル>
git commit -m "変更内容"
git push
```

別のPCでは `git clone https://github.com/shioa2006-game/dice-tactics-kingdom.git` で取得し、`launch.bat` または `npm start` で起動できます。原本のハッシュ照合を維持するため、`.gitattributes` で改行の自動変換を無効にしています。検証画像と出典資料も管理対象です。公開リポジトリのため、認証情報や個人用ファイルは追加しないでください。

## 検証の再実行

`npm test` で元ゲームから引き継いだ56テストと、保存した原本コアとの互換性16テスト、待機方向5テストと事前生成画像5テスト（計82件）を実行できます。参照元フォルダは不要です。`tests/reference/core/` は検証専用の固定比較基準です。詳細は [検証用原本の記録](tests/reference/README.md)、ゲーム仕様は [元ゲームのルール](docs/ORIGINAL_RULES.md) を参照してください。

ブラウザの **`/?qa=1`** は別の検証入口です。人工配置・固定6AP・合成PointerEventを使う入力試験と、標準配置・通常出目・実CPUによる通し対局を区別しています。試験による戦績・設定は終了時に復元します。通常ゲームではこのパネルも検証コードも読み込みません。

ブラウザ内の画面幅確認はスマートフォン実機の確認ではありません。実機の指の感触、iOS Safari、低性能端末の負荷、実際の音の聴取は未確認です。
